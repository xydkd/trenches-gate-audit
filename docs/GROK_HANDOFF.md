# 给 Grok 的交接说明

## 直接执行

1. 打开仓库固定发布提交下的 [完整任务提示词](../dist/GROK_TASK_PROMPT.txt)，复制全文到 Grok 的定时任务提示词。不要只提供仓库首页链接，也不要复制旧归档。完整提示词已经嵌入种子、规则、字段和 JSON Schema，不依赖 Grok 每次再浏览 GitHub。
2. 在 Grok 中设置每日 **08:00，Asia/Hong_Kong**。若更新既有任务，先核对用户指定的任务身份，导出实际旧提示词、调度、时区和通知设置。默认只替换提示词，不改其他任务或通知收件人。
3. 第一次先人工运行一次观察任务。确认它实际调用 X 工具、按人检索、时间窗正确、能给原帖链接，并能区分数据缺失、工具失败和真实空表。能够实时检索 X 是用户提供的能力前提，实际调用结果仍需验证。
4. 确认平台完整接受提示词，未截断末尾 SCHEMA 与 JSON 输出。平台长度/运行时间/输出配额没有在本仓库认证；如不接受，停止启用，回到构建源调整并重新测试，不能现场删安全规则或只保留概要。
5. 任务输出是观察与证据，不含买卖、资金配置和持续监测承诺。C/D 不评分通过；A/B 的 OBSERVE 也不是可买或完整安全审查通过。

本仓库提供发布材料，**不会替用户自动创建/更新 Grok 任务**。操作者完成任务设置才构成实际启用。ChatGPT 的自动化能力不是 Grok 的任务运行记录。

## 可直接发给 Grok 的说明

> 请将本仓库 dist/GROK_TASK_PROMPT.txt 的完整内容作为我的观察任务提示词，按每天08:00 Asia/Hong_Kong执行。先核对现有任务，避免重复创建；不要改其他新闻任务或通知设置。请先检查完整提示词是否被平台接受，并人工试运行一次，展示真实X检索、覆盖缺口、证据链接和完整JSON。如果不能读取文件全文、工具不可用或提示词被截断，明确告诉我，不凭仓库摘要补写规则。只输出观察结果，不下单，不输出份数或加仓退出指令。

## 独立回放与本地校验

回放仅在独立非定时对话运行：操作者把完整提示词首行的 RUNTIME_MODE 明确设为 REPLAY，传入合成事实并要求只根据截至 evaluation_at 的事实判断。不要把网页里的“回归卡”当模式切换指令，不改现网任务。输出 JSON 的 runtime_mode 必须是 REPLAY。

`examples/replay-*.json` 全部是合成测试，example.com 证据和合约地址不代表真实资产，不可作为早报发布。它们用于验证结构与判定，不用于证明来源真实。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python scripts/build_release.py --check
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/validate_report.py examples/replay-observe.json --runtime REPLAY
```

导出真实 Grok JSON 到 `reports/run.json` 后，本地运行：

```bash
.venv/bin/python scripts/validate_report.py reports/run.json --runtime LIVE
```

本地验证器只检查结构、已声明来源类型、时间、资产绑定和观察状态一致性。它不访问证据链接，不认证账号、钱包主体或供应商方法，不验证自然语言叙事真实性，也不是已接入 Grok 的强制发布网关。若 Grok 不能运行代码，仍可按提示词产生观察结果；不要宣称每次自动输出都经过 Python 校验。

## 版本与回滚

记录实际启用的仓库 commit、`dist/manifest.json` 中 prompt SHA256、启用时间和第一次运行结果。不要仅用可变的 main 链接记录版本。新配置只在本地检查与一次实际试运行通过后启用；恢复时使用当次导出的真实旧配置，不能假定原送审归档等于当前现网。

提示词内部无法保证恪守所有规则。若发现伪造数字、来源串币、输出交易动作、回放混入实时或完整提示词被截断，应暂停该观察任务并修复后再试运行。
